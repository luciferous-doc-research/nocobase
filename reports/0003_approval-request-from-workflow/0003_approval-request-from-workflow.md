# ワークフローから承認依頼を投げる方法

## 知りたいこと

0002の更問い。ワークフローから承認依頼を投げることはできるのか

## 目的

棚卸し作業の一環で、スケジュール実行されたワークフローから、承認依頼を投げたい。

## 調査サマリー

### 結論：ワークフローから承認依頼を投げることは可能です

NocoBase のワークフロー内から承認依頼を投げるには、以下の 2 つの実装方法があります。

### 実装方法1：Invoke Workflow ノード（推奨）

**最も推奨される方法です。**

スケジュール実行ワークフロー内に「Invoke Workflow」ノードを追加し、別の承認ワークフロー（Approval トリガーを持つワークフロー）を呼び出します。

```
スケジュール実行ワークフロー
    ↓
Invoke Workflow ノード
    ↓
承認ワークフロー（Approval トリガー）
```

**利点：**
- ネイティブなワークフロー間連携で実装可能
- 認証トークンなどの複雑な設定が不要
- ワークフロー管理上、関係が明示的で保守しやすい

**設定方法：**
1. Invoke Workflow ノードで呼び出すワークフロー（承認ワークフロー）を選択
2. トリガー変数を設定：承認対象のコレクションデータなどを指定
3. サブワークフロー（承認ワークフロー）の「Workflow Output」ノードで必要な出力を定義

### 実装方法2：HTTP Request ノードで API 直接呼び出し

**より細粒度の制御が必要な場合の選択肢です。**

HTTP Request ノードで `/api/approvals:create` API エンドポイントを直接呼び出します。

```json
{
  "collectionName": "コレクション名",
  "workflowId": ワークフロー ID,
  "data": { "フィールド名": "値" },
  "status": 1
}
```

**課題：**
- HTTP API 呼び出しには認証情報（Authorization ヘッダー、X-Role ヘッダー）が必須
- スケジュール実行時の有効なトークン取得方法がドキュメント上に明記されていない
- 実装時には、NocoBase のシステムレベルトークン取得方法の確認が必要

### スケジュール実行ワークフロー固有の考慮点

- ユーザーアクションによる実行ではなく、時間トリガーによる自動実行のため、ユーザーコンテキストが異なる
- 承認申請者（Initiator）をどのように指定するかが重要（詳細はドキュメント上に記載されていない）

## 完了サマリー

### 調査内容

1. **ワークフローノード**：HTTP Request ノード、Invoke Workflow ノード
2. **ワークフロートリガー**：スケジュール実行トリガー、Approval トリガー
3. **関連機能**：ワークフロー変数、トリガー変数、ワークフロー出力
4. **参照情報**：前回の承認プラグイン調査（0002）から得た API 仕様

### 調査対象ドキュメント

英語版：5 ファイル
- workflow/nodes/request.md（HTTP Request）
- workflow/nodes/subflow.md（Invoke Workflow）
- workflow/triggers/schedule.md（スケジュール実行）
- workflow/advanced/variables.md（変数）
- workflow/nodes/index.md（ノード一覧）

日本語版：1 ファイル
- workflow/nodes/subflow.md（ワークフローの呼び出し）

### 実装推奨事項

**最優先：Invoke Workflow ノードを使う方法**
- ドキュメント上で実装方法が明確
- 複雑な認証処理が不要
- スケジュール実行ワークフローとの相性が良い

**セカンダリ：HTTP Request ノード + API 直接呼び出し**
- 詳細な制御が必要な場合のみ検討
- 認証トークン取得方法の追加調査が必要
- 実装試験で動作確認が必須
